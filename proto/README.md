# Protocol sources and language bindings

`v1/whalerein.proto` is the only message schema. `v1/WIRE.md` defines its wire
encoding, topics, framing and error semantics. `v1/fixtures/` contains wire
examples; cross-language test vectors live in `tests/fixtures/`.

| Location | Ownership |
| --- | --- |
| `v1/bindings/go/whalerein.pb.go` | Committed Go output generated by `./repo proto`. |
| `v1/bindings/go/json_wire_test.go` | Hand-written Go wire tests beside the generated package. |
| `v1/bindings/rust/` | Rust protocol crate, including hand-written build configuration and wire tests. Generated Rust types are written to Cargo's `OUT_DIR`. |
| `../host/runtime/src/generated/whalerein.json` | Committed protobufjs descriptor generated by `./repo proto`, colocated with its runtime consumer for package distribution. |
| `v1/error_codes.json` | Golden `ErrorCode` table: number, CLI exit code and client action. Core, the Host runtime and WIRE.md must agree with it. |
| `v1/compat/baseline.json` | Frozen schema baseline. Additions are compatible; removals, tag reuse, type/JSON-name changes and oneof membership changes fail. |
| `v1/compat/vectors.json` | Portable old/new reader vectors for unknown fields, unknown enums, a missing oneof and 64-bit integers near 2^53. |
| `v1/compat/surface.json` | Route, topic, type and error-code snapshot checked against WIRE.md, the generated descriptor and the Harness contract. |
| `v1/bindings/swift/ios-surface.json` | Swift-visible classification of every wire error code, including recorded mobile follow-ups. |
| `v1/bindings/swift/check_swift_surface.py` | Script-level drift check for the generated UniFFI Swift module and the flat mobile error surface. |

The `bindings` directory groups generated language bindings with hand-written
build configuration and wire tests. Edit the schema when changing messages, and
maintain the build/test scaffolding directly. Run `./repo proto --check` to verify
committed Go and JavaScript artifacts. Rust types regenerate into Cargo's
`OUT_DIR` during a build.

## Compatibility workflow

The compatibility policy is documented in [WIRE.md](v1/WIRE.md) and implemented
in `bindings/rust/src/compat.rs`, `bindings/go/compat.go` and
`host/runtime/src/protocol.js`. Adding a field is additive; an unknown enum
value and a missing oneof are explicit errors.

```bash
python3 tests/integration/drivers/protobuf/proto_compat.py --check
python3 proto/v1/bindings/swift/check_swift_surface.py
./repo test --project proto
./repo test --suite integration --group protocol
```

`proto_compat.py --check` compares the compiled descriptor with both the frozen
baseline and the exact snapshot. `--write` refreshes the snapshot and absorbs
additive baseline growth, but refuses a breaking change; `--update-baseline
--rationale TEXT` is the only path that records a reviewed breaking change and
appends it to `v1/compat/CHANGELOG.md`. The Rust `compat` tests enforce the same
rules during `./repo test --project proto`, so regenerating bindings cannot
silently bless a deletion, a reused tag number or a changed oneof.
