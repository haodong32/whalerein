# 规范增量


## Purpose

从原会话已完成的轮次创建另一条远程对话，保留清晰的父子身份和恢复语义，同时不暴露原生历史位置，也不暗示文件系统隔离。

## ADDED Requirements

### Requirement: 从完整轮次分叉对话

系统 SHALL 按原生来源选定的最近完整轮次分叉既有会话，不提交子会话提示词。

<a id="ac-01"></a>
#### Scenario: AC-01 分叉最近完整轮次

- **WHEN** 已授权客户端分叉包含完整轮次的空闲会话
- **THEN** 结果确认一个不同的子会话身份，标明源父会话，并允许通过子身份读取继承的完整上下文，不新增用户提示词

<a id="ac-02"></a>
#### Scenario: AC-02 后续轮次运行中进行分叉

- **WHEN** 分叉开始时，源会话已有完整轮次，其后还有运行中或排队的任务
- **THEN** 原生选定的完整前缀定义子会话；后续源任务不会由子会话自动执行，源会话不被中断或修改

<a id="ac-03"></a>
#### Scenario: AC-03 拒绝没有完整轮次的来源

- **WHEN** 源会话不存在或没有完整轮次
- **THEN** 请求返回 not_found/conflict；若原生阶段无法证明发生在子会话变更前，则返回保守的 `unknown`，两种情况都不创建空白替代子会话

### Requirement: 不透明边界与独立身份

系统 MUST 隐藏原生切点，并保持源会话与子会话的历史／缓存身份独立。

<a id="ac-04"></a>
#### Scenario: AC-04 拒绝任意历史切点

- **WHEN** 客户端提供任意原生序号或显式切点选项
- **THEN** 公开命令在变更前拒绝不支持的参数，绝不通过游标运算猜测切点

<a id="ac-05"></a>
#### Scenario: AC-05 保持父子会话独立

- **WHEN** 子会话创建后，分别读取、订阅并继续两个会话
- **THEN** 源会话保留既有历史视图和订阅；子会话拥有独立基线、游标和会话范围内的临时 Attempt 状态；子会话更新绝不覆盖源会话缓存消息

### Requirement: 能力与授权

系统 SHALL 要求目标 Host 的有效授权和明确的分叉能力；系统 MUST 在变更前拒绝过期命令。

<a id="ac-06"></a>
#### Scenario: AC-06 拒绝不支持未授权和过期请求

- **WHEN** 目标未宣告分叉能力、设备缺少有效授权、源会话属于另一个 Host，或命令在接纳前过期
- **THEN** 不发生原生分叉；不支持时返回 unsupported_capability，未授权调用不披露源详情，既有控制仍可使用

### Requirement: 已知的子会话部分创建

系统 SHALL 区分已确认创建但工作区绑定失败的子会话、变更前失败和未知结果。

<a id="ac-07"></a>
#### Scenario: AC-07 报告工作区绑定警告

- **WHEN** 原生分叉确认子会话身份，但随后工作区绑定失败，且绑定阶段无法被原生证明
- **THEN** 结果返回保守的 `unknown`，不声称 `READY_WITH_WARNING`、不删除子会话、不重复分叉；只有原生明确证明子/父身份和绑定阶段时才保留身份并返回警告

<a id="ac-08"></a>
#### Scenario: AC-08 变更后保留不确定性

- **WHEN** 子会话可能已创建后，原生执行或结果日志持久化失败，且没有可靠确认回执
- **THEN** 结果保持 unknown；不返回猜测的子身份或确定未创建子会话的失败，恢复绝不再次执行分叉

### Requirement: 持久化去重

系统 MUST 对每个保留的设备／命令身份至多调用一次原生分叉，并在不重新提交的情况下恢复原结果。

<a id="ac-09"></a>
#### Scenario: AC-09 跨并发和重启去重

- **WHEN** 同摘要重复分叉请求并发到达或在重启后到达，或重复请求改变原摘要
- **THEN** 同摘要重复请求重放原接纳状态／结果和已确认子身份，最多调用一次；拒绝改变摘要的请求

<a id="ac-10"></a>
#### Scenario: AC-10 允许有意创建独立分支

- **WHEN** 不同有效命令身份并发分叉同一源会话
- **THEN** 每次确认的操作返回独立子身份；原生来源为每次操作选择完整前缀，不跨命令合并

### Requirement: 明确范围与隐私

系统 SHALL 将分叉描述为对话操作，并 SHALL 保持离线和私有数据边界。

<a id="ac-11"></a>
#### Scenario: AC-11 说明共享工作目录

- **WHEN** 通过人类可读输出、JSON 或长期维护的使用文档展示分叉
- **THEN** 已知时明确子会话实际目录，面向人的使用说明指出对话分叉不创建 worktree 或文件系统隔离，也不暗示覆盖模型或预设

<a id="ac-12"></a>
#### Scenario: AC-12 保持离线和诊断边界

- **WHEN** 客户端离线分叉，或收集合成分支流程的运行诊断和验收证据
- **THEN** 离线控制被拒绝，不排队执行变更；继承消息内容、工具参数、原生事件序号、凭据或原始原生错误不进入日志或测试证据；Host 持久化生命周期回执不包含 cwd、工作区标识或预设内容
