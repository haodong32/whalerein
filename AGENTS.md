# WhaleRein Guidelines

- Use English for code, comments, and developer docs; `WhaleRein` for display names, `whalerein` for packages, paths, and keys.
- Keep changes focused and architecture simple; add dependencies or abstractions only for clear requirements.
- SDD tools are optional; repository workflows must remain usable without any specific SDD tool.
- Keep intermediate planning, task-tracking, and acceptance artifacts Git-ignored and out of commits, including artifacts generated by SDD tools. Use `.local-docs/plans/` and `.local-docs/acceptance/` for tool-independent working material. Preserve durable project facts and decisions in tracked `docs/` or clear code comments when needed, based on the implementation and verified behavior.
- Use `./repo` for monorepo tasks (`tools/repo/`, Python + uv). For task selection or runner changes, use [whalerein-repo](.agents/skills/whalerein-repo/SKILL.md).
- DSH owns sessions; access its APIs only through the plugin adapter.
- Keep Core self-contained in Rust; `SecretStore` is its only injection boundary.
- Use PostgreSQL for server state and internal tasks; review additional infrastructure before introducing it.
- Never commit secrets or expose message contents, tool parameters, private keys, or pairing tokens in logs or tests.
- Use staged validation: iterate with `./repo check TARGET` and `./repo test TARGET --only TEXT`; finish with affected-project unit tests and coverage once after the final relevant edit. Require ≥90% coverage per Rust crate, Go package, and Node.js package. Documentation-only changes need document checks.
- Before expanding or repeating tests, state the new relevant edit, failure, or uncovered risk. Choose integration targets by changed behavior; directory count alone does not justify full integration. Follow [test selection and timing policy](docs/testing.md#choose-checks-for-a-change); local command defaults remain available for intentional full validation.
- If a test cannot execute on the current operating system, skip it with an explicit platform reason; do not emulate, cross-run, or force it. Gate OS-specific tests (`cfg`, build tags, `t.Skip`, `pytest.mark.skipif`) so the matching GitHub Actions OS job runs them. A skip on another OS is not evidence.
- Claim only verified API, integration, and deployment behavior.
- Before committing, read [commit rules](docs/commits.md).
- Before creating or updating a PR/MR, read [pull request rules](docs/pull-requests.md).
